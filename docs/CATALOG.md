# 제도 목록 관리 (catalog)

답변에 쓰이는 제도의 **전체 목록을 웹에서 보고 추가·수정·숨김·삭제**하는 기능. A가 API로 받은 제도(SQLite)와 검색 색인은
직접 고치지 않고, 사람이 한 변경을 **덧씌움(overlay)** 으로 따로 쌓는다.

```powershell
python -m app.catalog_mode            # 웹 화면 (목록 검색·수정·추가·숨기기·색인 반영)
python -m src.catalog stats           # 추가·수정·숨김 현황
python -m src.catalog apply --dry-run # 색인에 반영할 변경 미리 보기 (--dry-run을 빼면 반영, 임베딩 모델 필요)
```

## 왜 덧씌우나
- API 제도를 DB에서 직접 고치면 다음 수집에서 덮어쓰이고, 누가 왜 바꿨는지 남지 않는다.
- 덧씌움은 `catalog/events/<편집자>.jsonl`에 **추가만** 한다 (검수 저장소와 같은 방식, 사람마다 파일이 달라 git 충돌이 없다).
  이력이 남고, 모든 변경을 되돌릴 수 있다.

## 화면 쓰는 법
목록 표에서 제도의 **맨 왼쪽 선택 칸을 클릭**하면 바로 아래에 그 제도의 내용과 수정 칸이 열린다 (스크롤로 목록을 뒤질 필요 없음). 저장·숨기기를 해도 같은 제도가 계속 열려 있고, "선택 닫기"로 닫는다. Streamlit 표에는 더블클릭 동작이 없어 한 번 클릭으로 연다. 오래된 Streamlit(표 선택 기능 없음)에서는 표 아래 목록에서 고른다.

## 할 수 있는 일

| 일 | 이벤트 | API 제도 | 직접 추가한 제도 | 답변에 반영되는 때 |
|---|---|---|---|---|
| 새 제도 추가 | `add` | - | 가능 (ID는 `MAN-…`) | **색인에 반영** 후 |
| 값 수정 | `edit` | 가능 (바뀐 항목만 기록) | 가능 | 색인에 반영 후 |
| 원본 값으로 되돌리기 | `revert` | 가능 | - | 색인에 반영 후 |
| 답변에서 숨기기·복구 | `hide`·`unhide` | 가능 | 가능 | **바로** (숨김), 복구는 색인에 반영 후 |
| 삭제 | `remove` | 불가 (숨기기를 쓴다) | 가능 | 색인에 반영 후 |

수정 가능한 항목: 서비스명, 소관기관, 분야, 지원대상, 선정기준, 지원내용, 신청방법, 신청기한, 상세 링크.
입력 규칙: 서비스명은 비울 수 없고, 새 제도는 지원대상·지원내용 중 하나가 필요하며, 상세 링크는 `https://`만 (인증키가 든 주소 불가).

## 동작 방식
- **숨김**: 생성 단계(`generator._answer_with_evidence`)가 검색 결과에서 숨긴 제도를 바로 뺀다 (`catalog.store.hidden_ids`, 파일이 바뀔 때만 다시 읽음). 터미널 추적(`RAG_TRACE=1`)에 "관리자가 숨긴 제도"로 나온다.
- **색인 반영(`apply`)**: 숨긴·삭제한 제도는 색인에서 지우고, 추가·수정·숨김 해제한 제도는 A의 분할기(`chunker.chunk_service`)로 조각을 다시 만들어 B의 `vector_store.build_index`로 넣는다. 같은 조각 ID로 덮어쓰므로 여러 번 실행해도 같다.
- 수정한 API 제도의 기한·지역 근거는 A의 `refresh_service`로 다시 계산한다. 직접 추가한 제도는 A의 `clean_service`로 정규화한다.

## 한계와 주의
- **A의 수집이 같은 제도를 다시 색인하면 수정이 색인에서 덮어써진다.** 수집 뒤에는 `apply`를 다시 실행한다. 숨김은 색인과 상관없이 답변 단계에서 계속 적용된다.
- `apply`는 `handoff`의 잠금·확인(ack)을 거치지 않는 B의 직접 색인이다. 수집(`handoff --apply`)과 동시에 실행하지 않는다.
- 덧씌운 값은 A의 SQLite(`data/services.db`)에 들어가지 않는다. 검수 화면(`app.review_mode`)·평가의 baseline·`src.review`는 DB만 보므로 직접 추가한 제도는 그쪽에 나오지 않는다.
- 변경을 되돌려도 `apply`를 다시 실행해야 색인이 원래대로 돌아간다 (숨김만 바로 반영).
- 편집자 이름은 신원 확인이 아니다 (검수 저장소와 같음). 누가 바꿨는지는 git 기록과 이벤트 파일로 본다.
