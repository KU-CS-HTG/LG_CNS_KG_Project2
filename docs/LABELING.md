# 평가 질문 정답 채우기 안내

`eval/questions.jsonl`의 질문마다 **정답 제도의 `service_id`** (`relevant_service_ids`)를 채우는 방법입니다.
정답을 채워야 검색 평가(`python -m eval.run_eval`)가 의미 있는 점수를 냅니다. 팀원 전원이 함께 하는 작업이고,
도구는 [`eval/label_helper.py`](../eval/label_helper.py)입니다. (평가 지표와 실행법은 README 7장)

## 0. 5분 요약

```powershell
git pull origin <내 브랜치>                      # 1. 최신 질문 파일 받기
pip install -r requirements.txt                  # 2. 처음 한 번
python -m eval.label_helper fetch                # 3. 보조금24 서비스 목록 내려받기 (처음 한 번, .env에 GOV24_API_KEY 필요)
python -m eval.label_helper status               # 4. 진행 상황 (정답 미지정 문항 수)
python -m eval.label_helper label --only q01,q02 # 5. 내 담당 문항만 대화형으로 채우기
python -m eval.label_helper check                # 6. 검증 (오류 0건이 될 때까지)
git add eval/questions.jsonl && git commit -m "eval: q01,q02 정답 지정"   # 7. 커밋·푸시
```

핵심 규칙 세 가지만 기억하세요.
1. **내가 데이터를 읽고 판단해서** 고른다. 우리 검색 시스템의 결과를 베끼지 않는다 (§3).
2. 질문 하나에 정답은 **5개 이내**, 그 제도 하나만으로 좋은 답이 되는 것만 (§3).
3. **지역이 없는 질문은 전국 단위 제도**를 정답으로 하고, 지역 제도는 `followup`으로 만든 별도 문항에서 채운다 (§6).

## 1. 무엇을 채우나

질문 한 줄(JSON)은 이렇게 생겼습니다. 정답이 비어 있고 `todo`가 남아 있는 상태입니다.

```json
{"id": "q22", "category": "상황형", "topic": "주거",
 "question": "월세 계약을 해야 하는데 보증금이 부족해요. 보증금을 빌려주거나 보증해 주는 제도가 있나요?",
 "relevant_service_ids": [],
 "expected_answer": "보증금 대출·보증 지원 제도를 안내한다.",
 "expect_no_answer": false,
 "todo": "수집 후 데이터를 읽고 정답 service_id 지정 (데이터에 없는 제도·상황이면 질문 수정)"}
```

채운 뒤에는 도구가 이렇게 바꿉니다 (`todo`가 지워지고, 사람이 확인하기 쉽게 제도 이름이 함께 기록됨).

```json
 "relevant_service_ids": ["116010000001", "700000000002"],
 "relevant_service_names": ["주택금융공사 월세자금보증", "청년 월세 한시 특별지원"],
 "expect_no_answer": false
```

- **정답**이란 "이 질문에 대해 우리 시스템이 찾아와야 하는 제도"입니다. 검색 결과 상위 5개 안에 정답이 있는지(Hit Rate),
  정답 중 몇 개를 찾았는지(Recall), 첫 정답이 몇 위인지(MRR)로 점수를 냅니다.
- `service_id`는 보조금24의 **서비스ID** 값 그대로입니다 (조각 id `…#지원대상`이 아님).
- `relevant_service_names`는 사람이 눈으로 검수하라고 도구가 적어 두는 값이며 점수 계산에는 쓰이지 않습니다.

질문의 상태는 네 가지이고 `status` 명령이 개수를 보여 줍니다.

| 상태 | 뜻 | 평가에서 |
|---|---|---|
| 정답 지정 | `relevant_service_ids`가 있음 | Hit Rate·Recall·MRR 계산에 쓰임 |
| 근거 없음 확정 | `expect_no_answer: true`, `todo` 없음 | 검색 지표에서 빠지고, "빈 결과를 돌려주는지"를 따로 봄 |
| 근거 없음(확인 필요) | `expect_no_answer: true`인데 `todo`가 남음 | 위와 같음. 데이터를 확인하고 `keep`/`none`/정답 지정으로 확정해야 함 |
| 정답 미지정 | 정답도 `expect_no_answer`도 없음 | **평가에서 제외**됨. 채울수록 평가 문항이 늘어남 |

## 2. 준비 (처음 한 번)

1. 코드를 최신으로 받고 설치합니다.
   ```powershell
   git pull origin <내 브랜치>
   pip install -r requirements.txt
   ```
2. `.env`에 보조금24 인증키를 넣습니다 (`.env.example`을 복사). **Decoding 키**여야 하고, 공공데이터포털에서 활용신청이 승인돼 있어야 합니다.
   ```
   GOV24_API_KEY=발급받은_Decoding_키
   ```
3. 서비스 목록을 내려받습니다. 약 1만 건이며 한 번만 하면 됩니다. 결과는 `data/raw/serviceList.json`에 저장되고 git에는 올라가지 않습니다.
   ```powershell
   python -m eval.label_helper fetch
   python -m eval.label_helper fields      # 실제 응답에 어떤 필드가 있는지, 전국/지역 구분이 되는지 확인
   ```
   - **팀 전원이 각자 받을 필요는 없습니다.** 한 명이 받은 `data/raw/serviceList.json`을 메신저 등으로 공유해 같은 위치에 두면 됩니다.
   - A의 수집이 같은 이름의 파일을 이미 만들었다면 그대로 사용합니다 (이미 있으면 `fetch`가 멈추고 알려 줌. 다시 받으려면 `--force`).
   - `fields`에서 "꼭 필요한데 찾지 못한 항목"이 나오면 `eval/label_helper.py` 위쪽 `ALIASES`를 실제 필드 이름에 맞게 고쳐야 합니다.
     "선택 항목 중 찾지 못한 것"은 없어도 동작하지만, `신청기한`이 없으면 기한 경고가, `소관기관`이 없으면 전국/지역 구분이 부정확해집니다.
4. `python -m eval.label_helper status`로 질문 파일이 읽히는지 확인합니다.

내려받기에 실패하면: 인증키가 Decoding 키인지, 활용신청이 승인됐는지, 네트워크가 막혀 있지 않은지 확인하세요 (`403`/`SERVICE_KEY` 오류는 대개 키 문제).

## 3. 정답을 정하는 기준 (가장 중요)

### 3.1 포함하는 제도

- **그 제도 하나만으로도 이 질문에 대한 좋은 답이 되는** 제도입니다.
- 질문이 밝힌 조건(청년, 월세, 취업 준비, 지역, 나이 등)과 **모순되지 않고**, 질문이 묻는 필요를 **직접** 다루어야 합니다.
- 소득·가구·재산처럼 **질문에 나오지 않은 자격 조건은 따지지 않습니다.** 그건 답변 단계에서 "확인 필요"로 처리되는 부분이라, 여기서는 "해당될 가능성이 있는가"만 봅니다.

### 3.2 제외하는 제도

| 제외 | 이유 |
|---|---|
| 신청기한이 **이미 지난** 제도 | 서비스는 기한이 지난 제도를 안내하지 않음 (도구가 `[기한 지남?]`으로 경고) |
| 질문과 **조금만 관련 있는** 제도 | 정답이 늘어 Recall이 낮아지고 사람마다 기준이 달라짐 |
| 대상이 **청년이 아닌** 제도 (노인, 영유아 등) | 1차 범위가 청년층 (README 1.1) |
| 지역만 다른 **같은 제도의 다른 버전** | 질문의 지역에 맞는 것만. 지역이 없으면 전국 단위 제도를 우선 (§3.4) |

### 3.3 개수: 5개 이내

- Recall@5는 `상위 5개 안의 정답 수 ÷ 전체 정답 수`라서, 정답을 11개 적으면 아무리 잘 찾아도 최대 5/11 ≈ 0.45입니다 (목표 0.70).
  Hit Rate와 MRR은 정답이 몇 개든 영향이 적습니다.
- 해당되는 제도가 5개보다 많으면 **가장 직접적인 5개**를 고르거나, 질문을 더 구체적으로 바꿉니다.
- 모든 가능한 제도를 찾으려고 애쓰지 마세요. 약 1만 건을 다 읽을 수 없으므로 "내가 아는 한 확실한 핵심 후보"면 충분합니다.
  나중에 검색 결과에서 정답 목록에 없는데 맞는 제도가 발견되면 그때 추가합니다 (§10).

### 3.4 지역 규칙 (서비스 흐름 기준)

실제 사용자는 처음에 **지역 없이** 묻고, 서비스가 **추가 질문으로 지역을 받습니다.**

| 문항 | 정답 |
|---|---|
| 지역이 없는 질문 (예: q01) | **전국 단위 제도** (중앙부처·공공기관) |
| 지역을 알려 준 뒤 질문 (예: "서울에 살아요. …") | **그 지역 제도 중심 + 전국 제도 일부** |

그래서 도구는 지역 없는 질문에서는 전국 단위 제도만 보여 주고, 지자체 제도를 고르면 경고합니다. 지역 문항은 `followup` 명령으로 만듭니다 (§6).

### 3.5 복합 질문

"월세가 부담되고 취업을 준비 중"처럼 필요가 둘이면 **각각 따로 찾아서** 주거 쪽 2~3개, 구직 쪽 2~3개를 고릅니다 (합쳐서 5~6개 이내).
둘 중 어느 쪽이 검색돼도 Hit Rate가 맞고, 둘 다 찾으면 Recall이 올라갑니다.
두 키워드를 한꺼번에 넣어 검색하면 **두 단어가 모두 들어 있는 제도**만 나와 좋은 후보가 빠지니, 필요마다 따로 검색하세요.

### 3.6 가장 중요한 금지: 검색 결과 베끼기

정답을 우리 시스템의 검색 결과(`python -m src.retrieve.hybrid …`, 앱 화면)에서 골라 쓰면 **검색이 찾은 것만 정답**이 되어 점수가 부풀려집니다.
정답은 **원본 데이터를 읽고** 정합니다. 이 도구의 키워드 검색은 "후보를 눈으로 찾는 용도"이고, 우리 RAG 검색과는 별개입니다.

## 4. 대화형으로 채우기 — `label`

```powershell
python -m eval.label_helper label                    # 정답이 비어 있는 모든 문항을 차례로
python -m eval.label_helper label --only q01,q02     # 내 담당 문항만
python -m eval.label_helper label --all              # 이미 채운 문항도 다시 보기
```

질문이 하나씩 나오고 `>` 프롬프트에 명령을 입력합니다. **한 문항을 저장(`ok`)할 때마다 파일에 바로 반영**되므로 중간에 `quit`해도 여기까지는 저장되어 있습니다.

### 4.1 명령

| 입력 | 하는 일 |
|---|---|
| (글자) 예: `월세` | 그 키워드로 검색. 여러 단어는 **모두 포함**. 결과가 없으면 "하나라도 포함"으로 자동 재검색 |
| `1 3` | 방금 결과의 1번·3번을 정답 후보에 추가 (한 번 더 입력하면 해제) |
| `d 2` / `D 2` | 2번 제도를 자세히 읽기 (`D`는 줄이지 않고 전체) |
| `more` | 다음 10건 |
| `id:116010000001` | 서비스ID를 직접 추가 |
| `chosen` / `clear` | 고른 후보 보기 / 비우기 |
| `region 서울` / `region off` | 서울 제도 + 전국 제도로 보기 / 해제 |
| `scope national` / `local` / `all` | 전국 단위만 / 지자체만 / 전부 |
| `expired on` / `expired off` | 기한이 지난 듯한 제도 보기 / 숨기기 |
| `youth` | 청년 키워드(청년·대학생·사회초년생·취업준비 등)가 있는 제도만 (켜고 끄기) |
| `view` | 현재 보기 설정 |
| `ok` | 후보를 이 문항의 정답으로 **저장**하고 다음 문항으로 |
| `none` | 찾아봤지만 맞는 제도가 데이터에 없다 → "근거 없음"으로 확정 (확인 질문 후) |
| `keep` | (이미 근거 없음인 문항) 데이터를 확인했고 그대로 둔다 |
| `skip` (또는 엔터) | 건너뛰기 |
| `quit` | 종료 |
| `help` | 명령 안내 |

### 4.2 검색 결과 읽는 법

```
  1. 116010000001  주택금융공사 월세자금보증  | [전국] 한국주택금융공사 · 주거·자립 · 기한 주택도시기금 주거안정 월세대출 규정에 따름
  2. 700000000002  청년 월세 한시 특별지원  | [전국] 국토교통부 · 주거·자립 · 기한 2026.01.01~2026.12.31 [진행중]
```

- `[전국]` / `[서울]` / `[경남]` / `[지역미상]`: 소관기관 이름으로 **추정한** 범위입니다 (시·도 이름으로 시작하면 그 지역 제도).
- `[기한 지남?]` / `[진행중]`: 신청기한 문자열에서 끝나는 날짜를 읽어 **추정**한 것입니다. 표시가 없으면 상시·공고·"접수기관 별 상이" 등 판단할 수 없는 경우입니다.
- 결과 위에 `(숨김: 지역·범위 때문에 5건, 기한이 지난 듯해서 1건)`처럼 숨긴 개수가 나옵니다. 의심되면 `scope all`, `expired on`으로 확인하세요.

### 4.3 한 문항을 채우는 예 (아래 제도는 설명용 가짜 데이터)

```
[1/1] q01  (상황형 / 주거·구직)  상태: todo
질문: 월세가 부담되고 취업을 준비하고 있는데 받을 수 있는 지원이 있을까요?
기대 답변: 주거·구직 지원 후보를 안내하고, 소득·가구 기준은 이어서 질문한다.
[지역 없음] 서비스는 지역을 추가 질문으로 받으므로, 이 질문의 정답은 전국 단위 제도로 정합니다. ...
> 월세
  2건 표시  (숨김: 지역·범위 때문에 5건)
  1. 116010000001  주택금융공사 월세자금보증  | [전국] 한국주택금융공사 · 주거·자립 · 기한 주택도시기금 ...
  2. 700000000002  청년 월세 한시 특별지원  | [전국] 국토교통부 · 주거·자립 · 기한 2026.01.01~2026.12.31 [진행중]
> d 2                         ← 2번을 읽어 본다 (대상·선정기준·기한 확인)
■ 청년 월세 한시 특별지원   (서비스ID: 700000000002)
  [범위] 전국   [기한 판정] 진행 중으로 보임 (끝 2026-12-31)
  [지원대상] 청년 월세 지원 ...
> 1 2                         ← 읽어 보고 맞다고 판단한 두 제도를 추가
  추가: 주택금융공사 월세자금보증
  추가: 청년 월세 한시 특별지원
> 구직                         ← 이번에는 구직 쪽을 따로 검색
  1. 700000000003  청년 구직활동 지원금  | [전국] 고용노동부 · 고용·창업 · 기한 2026.03.01~2026.12.31 [진행중]
  2. 700000000001  국민취업지원제도  | [전국] 고용노동부 · 고용·창업 · 기한 상시신청
> 1
  추가: 청년 구직활동 지원금
> chosen
  고른 후보: 116010000001(주택금융공사 월세자금보증), 700000000002(청년 월세 한시 특별지원), 700000000003(청년 구직활동 지원금)
> ok
  저장: q01 ← ['116010000001', '700000000002', '700000000003']
```

**저장할 때 경고**: 고른 제도가 질문과 안 맞으면 (`ok` 시) 이렇게 알려 주고 확인합니다. `n`이면 저장하지 않습니다.
```
  ! 경상남도 청년 월세 지원: 지역이 없는 질문인데 지자체 제도입니다 (경남). 지역을 받은 뒤 질문(followup)의 정답으로 두세요
  ! 서울시 청년 월세 지원: 신청기한이 지난 것으로 보입니다
  그래도 저장할까요? (y/N)
```

### 4.4 검색 요령

- **한두 단어씩, 핵심어로** 찾으세요. `월세`, `보증금`, `구직`, `취업준비`, `장학금`, `학자금`처럼 짧은 단어가 잘 걸립니다.
- 같은 뜻의 **다른 말**로도 찾으세요 (월세/임차료/주거비, 구직/취업/일자리). 한 번 검색으로 판단하지 마세요.
- 결과가 너무 많으면 `youth`로 청년 키워드 필터를 켜고, 지역 문항이면 `region`을 쓰세요.
- 제목만 보고 고르지 말고 **`d 번호`로 지원대상·선정기준·기한을 읽은 뒤** 추가하세요.
- 결과 순서는 단순한 키워드 일치 점수일 뿐 **좋은 순서가 아닙니다.** 위에 있다고 정답이 아닙니다.

## 5. 질문 유형별 가이드

| 유형 | 어떻게 채우나 |
|---|---|
| **상황형** (제도명을 모르고 상황으로 묻는 질문) | §3 기준대로 필요마다 검색해 2~5개. 지역이 없으면 전국 단위 제도 |
| **제도명 아는 질문** (예: 근로장려금, 청년도약계좌) | 그 이름으로 검색해 **데이터에 실제로 있는지** 확인. 이름이 다르면(예: "청년도약계좌"가 데이터에 없음) 데이터에 있는 비슷한 제도 이름으로 **질문을 고치세요.** 같은 이름의 제도가 여러 개면 가장 해당하는 1~2개 |
| **지역·연령 조건** (서울 27세 등) | 질문의 `filters`에 조건이 이미 있습니다. 도구가 자동으로 **그 지역 제도 + 전국 제도**를 보여 줍니다. 그 지역 제도 중심으로 고르고, 연령 범위가 안 맞는 제도(예: 만 35세 이상)는 제외 |
| **기한 지난 제도** (예: 청년희망적금) | 처음부터 `근거 없음(확인 필요)` 상태입니다. 데이터에서 그 제도의 신청기한이 **정말 지났는지** 확인하세요. 지났거나 데이터에 없으면 `keep`. 아직 신청 가능하거나 대체 제도가 있으면 정답을 지정하거나, **기한이 지난 다른 실제 제도**로 질문을 바꿉니다 (`expired on`으로 지난 제도 찾기) |
| **근거 없음** (신설 예정 제도, 청년 범위 밖, 없는 제도) | 키워드를 **3가지 이상** 바꿔 검색해도 맞는 제도가 없을 때만 `none`/`keep`. 범위 밖 질문(예: 기초연금)은 청년 범위(README 1.1)가 바뀌면 다시 판단 |

**질문을 고치거나 지우는 법**: `eval/questions.jsonl`의 해당 줄을 직접 수정하거나 삭제하면 됩니다. id가 건너뛰어도 괜찮습니다.
단, 테스트(`tests/test_run_eval.py`)가 "질문 30개 이상, 다섯 범주 모두 포함, 상황형이 절반 이상"을 확인하므로 삭제로 이 기준이 깨지면 대체 질문을 추가하세요.
질문 문장은 **제도를 모르는 일반인이 쓸 법한 말투**를 유지하세요.

## 6. 지역 후속 질문 — `followup`

지역이 있어야 안내할 수 있는 제도(월세, 교통비, 청년수당 등)는 "지역을 알려 준 뒤의 질문"을 별도 문항으로 만들어 정답을 채웁니다.

```powershell
python -m eval.label_helper followup q01 --region 서울
# → 새 문항 q35 를 q01 뒤에 추가했습니다 (지역 서울).
python -m eval.label_helper label --only q35
```

- 새 문항은 `category: "지역 후속 질문"`, `filters: {"region": "서울"}`, `follow_up_of: "q01"`이고 질문은 "서울에 살아요. <원 질문>"입니다.
  문장을 직접 정하려면 `--text "서울에 사는데 월세가 부담되고 취업을 준비하고 있어요"`, 나이도 조건에 넣으려면 `--age 27`을 붙입니다.
- **q01과 q35 둘 다 채워야 합니다.** q01(지역 없음)은 전국 단위 제도, q35(서울)는 **서울 제도 중심 + 전국 제도 일부** (5개 이내).
  q35에 전국 제도만 넣으면 지역 필터가 잘 동작하는지 시험할 수 없습니다.
- **모든 문항에 만들지 마세요.** 정답이 지역별 제도에 많이 의존하는 질문(주거·교통·창업 등)에만, 지역은 서울 하나(많아야 한두 개 더)로 충분합니다.
  국민취업지원제도처럼 전국 단위로 답이 정해지는 질문은 필요 없습니다.

## 7. 명령 모음 (대화형 없이)

모두 `python -m eval.label_helper <명령>` 형태입니다.

| 명령 | 설명 |
|---|---|
| `fetch [--force] [--key 키]` | 서비스 목록 내려받기 |
| `fields` | 응답 필드 확인, 전국/지역 구분과 기한 판정 예시 |
| `search 단어… [--any] [--youth] [--region 서울] [--scope national\|local\|all] [--show-expired] [--limit 20] [--today 2026-10-19]` | 키워드 검색 |
| `show 서비스ID [--full]` | 한 제도 자세히 |
| `label [--only q01,q02] [--all]` | 대화형 채우기 |
| `followup 질문id --region 서울 [--text …] [--age 27]` | 지역 후속 문항 만들기 |
| `set 질문id ID1 ID2 …` | 정답을 직접 지정 (경고는 보여 주되 저장함) |
| `none 질문id` | 근거 없음으로 확정 |
| `set`·`none`에 `--source claude --note "근거" --confidence 중간` | 사람이 아닌 쪽이 채웠다는 출처를 함께 기록 (사람 검수 대기로 표시) |
| `apply 결정.json [--source claude]` | `{질문id: {ids, note, confidence, [no_answer], [todo]}}` 를 한꺼번에 반영 (id가 하나라도 없으면 아무것도 바꾸지 않음) |
| `review [--only q01,q02]` | 사람 검수 대기 목록과 근거 보기 |
| `review --ok q01,q02` / `review --all-ok` | 검수 완료로 표시 |
| `drop 질문id` | 질문을 세트에서 삭제(폐기). 후속 문항이 달린 질문은 후속을 먼저 삭제. 저장 전 백업이 `data/raw/label_backups/`에 남음 |
| `status` | 진행 상황 (정답 지정 / 근거 없음 / 확인 필요 / 미지정 수, 남은 문항 목록) |
| `check` | 정답 검증 (§8) |

`--today YYYY-MM-DD`는 기한 판정 기준일입니다 (기본은 오늘).

## 8. 검증

### 8.1 `check`

```powershell
python -m eval.label_helper check
```

| 출력 | 뜻 | 조치 |
|---|---|---|
| `! q05: 서비스ID '…' 가 데이터에 없음` | id 오타이거나 다른 데이터에서 가져온 id | id를 다시 확인 (**오류**, 종료 코드 1) |
| `! q05: … 의 이름이 다름` | 기록된 제도 이름과 id의 실제 이름이 다름 — id를 잘못 붙였을 가능성 | id 확인 (**오류**) |
| `! q32: 근거 없음인데 정답이 있음` | 모순된 상태 | 하나로 정리 (**오류**) |
| `~ 경고 q05: … 지역이 없는 질문인데 지자체 제도` | 전국 단위 기준에 안 맞음 | 전국 제도로 바꾸거나 `followup` 문항으로 옮김 |
| `~ 경고 q05: … 다른 지역 제도` / `신청기한이 지난 것으로 보입니다` | 질문의 지역·기한과 안 맞음 | 제도를 바꾸거나, 판정이 틀렸다면 원문을 읽고 유지 |
| `~ 경고 q05: 정답이 6개입니다` | Recall이 구조적으로 낮아짐 | 5개 이내로 줄임 |

**오류가 0건이 되게 하세요.** 경고는 사람이 판단해 남겨도 되지만 이유를 설명할 수 있어야 합니다 (PR 설명에 적어 주세요).

### 8.2 서로 검수하기 (권장)

정답은 사람의 판단이라 오류가 섞이기 쉽습니다. PR을 올릴 때 **다른 사람이 일부 문항(예: 문항당 정답 1개씩)을 `show 서비스ID`로 열어 보고**
정말 그 질문의 답이 되는지 확인하세요. `relevant_service_names`가 함께 기록되어 있어서 diff만 봐도 이름으로 어느 정도 판단할 수 있습니다.

### 8.2.1 Claude 1차 라벨링 + 사람 검수

시간을 아끼려고 1차 정답을 Claude가 실제 서비스 목록 데이터를 읽고 정한 경우, 문항에 다음 필드가 남습니다 (평가 계산에는 안 쓰임).

| 필드 | 설명 |
|---|---|
| `label_source` | 채운 주체 (`claude`). 사람이 `set`/`label`로 다시 지정하면 이 필드들은 지워지고 사람이 채운 것으로 봄 |
| `reviewed` | 사람이 검수했으면 `true` |
| `label_confidence` | 높음/중간/낮음 |
| `label_note` | 판단 근거 한 줄 (왜 이 제도를 넣고 무엇을 뺐는지) |
| `todo` | 사람이 꼭 결정해야 할 것 (근거 없음 질문의 데이터 확인, 질문 교체 등) |

검수 절차: `status`로 검수 대기 수를 보고 → `review`로 근거와 함께 훑어 보고 → 맞으면 `review --ok q01,q02`, 틀리면 `show 서비스ID`로 읽고 `set`으로 직접 고쳐 저장(사람이 채운 것으로 바뀜) → `check` 통과.
**검수 우선순위**: 신뢰도 낮음, `todo`가 있는 문항, 기한이 모호한 제도. 두 사람이 겹치게 일부(약 8문항)를 독립적으로 정해 보면 라벨 품질(일치율)을 확인할 수 있습니다.
검수를 마치기 전의 평가 결과는 LLM이 만든 정답(silver)에 기댄 것이므로 기획서 9.1/9.4에 그렇게 밝혀 적으세요.

### 8.3 평가를 돌려 보기

정답이 채워진 뒤, 색인이 있으면 검색 평가를 돌립니다 (README 7.1).
```powershell
python -m eval.run_eval --experiment all --today 2026-10-19
```
출력의 **"놓친 질문"** 목록에서 정답이 몇 위였는지, 어떤 제도가 대신 검색됐는지 볼 수 있습니다.
거기서 **검색된 제도가 사실 질문의 좋은 답이라면 사람이 읽고 확인한 뒤 정답에 추가**하세요 (정답 누락 보완). 읽지 않고 추가하면 안 됩니다 (§3.6).

## 9. 팀 작업 방식

### 9.1 분담 (제안, 담당자는 팀에서 정하세요)

`status`로 보이는 문항을 세트로 나눠 각자 자기 세트만 수정합니다.

| 세트 | 문항 | 내용 | 담당 |
|---|---|---|---|
| 1 | q01 ~ q12 | 구직·직업훈련·주거·교육·금융 | |
| 2 | q13 ~ q22 | 결혼·출산·양육·창업·건강·교통·자립·주거 | |
| 3 | q23 ~ q34 | 제도명 아는 질문, 지역·연령, 기한 지난 제도, 근거 없음 | |

`followup`으로 만든 문항은 원 질문 바로 뒤에 들어가고 id는 끝 번호 다음(q35, q36…)입니다. 만든 사람이 그 문항의 정답도 채웁니다.

### 9.2 절차

1. 작업 전에 `git pull`로 최신을 받습니다.
2. `label --only …`로 **내 문항만** 채웁니다. 한 문항을 끝낼 때마다 파일이 저장됩니다.
3. `check`에서 오류가 없는지 확인합니다.
4. 커밋하고 푸시합니다. **자주 커밋**하세요 (예: 문항 3~4개마다).
   ```powershell
   git add eval/questions.jsonl
   git commit -m "eval: q01~q04 정답 지정"
   git push
   ```
5. 합칠 때는 PR로 올리고, 다른 팀원이 §8.2대로 일부를 검수합니다.

### 9.3 충돌이 났을 때

`eval/questions.jsonl`은 **문항 하나가 한 줄**이라, 서로 다른 문항을 고쳤다면 보통 자동으로 합쳐집니다.
같은 줄(또는 바로 이웃한 줄)을 고쳤으면 충돌 표시(`<<<<<<<`, `>>>>>>>`)가 생깁니다.
- 표시된 곳에서 **양쪽 줄을 모두 살리되**, 같은 문항이 두 번 나오면 최신 쪽 한 줄만 남기세요. 파일 전체를 한쪽 버전으로 덮어쓰지 마세요 (다른 사람의 정답이 사라집니다).
- 충돌을 푼 뒤 `check`와 `status`로 문항 수와 정답이 그대로인지 확인합니다.
- 도구는 파일을 쓰기 전에 `data/raw/label_backups/`에 백업을 남깁니다 (git에는 올라가지 않음). 실수했다면 그곳의 파일을 `eval/questions.jsonl`로 복사해 되돌릴 수 있습니다.

## 10. 자주 겪는 문제

| 상황 | 해결 |
|---|---|
| 검색 결과가 너무 많다 (예: `월세` 111건) | `youth`로 청년 키워드만, `region`·`scope`로 지역을 좁히고, `d 번호`로 읽으며 기준에 맞는 것만 |
| 검색 결과가 너무 적다 | 단어를 줄이거나 동의어로 바꿔 보기. 두 단어는 모두 포함해야 해서 좋은 제도가 빠질 수 있음 (필요마다 따로 검색) |
| 정답이 되는 제도가 너무 많다 | §3.3 — 가장 직접적인 5개, 또는 질문을 더 구체적으로 |
| 질문의 상황이 데이터에 아예 없다 | 질문을 데이터에 있는 상황으로 고치거나, 정말 없으면 `none` (근거 없음 질문으로 활용) |
| 기한이 `접수기관 별 상이`, `상시` 등이다 | 판단할 수 없어 경고가 안 나옴. `d 번호`로 상세를 읽고, 지난 제도로 보이는 근거가 없으면 포함 |
| 전국/지역 구분이 이상하다 (전국 기관인데 지역으로 표시됨) | 기관 이름이 지역명으로 시작하는 경우(예: 인천국제공항공사)의 추정 오류. `scope all`로 보고 직접 판단 |
| `fetch`가 실패한다 | §2 — Decoding 키인지, 활용신청 승인, 네트워크 |
| 한글이 깨져 보인다 (Windows) | 터미널 글꼴/인코딩 문제. 파일 자체는 UTF-8로 안전하게 저장됨 |
| 정답을 잘못 저장했다 | `set 질문id 올바른ID…`로 덮어쓰거나, `data/raw/label_backups/`의 백업으로 복원 |
| 질문 파일이 사라졌거나 이상해졌다 | `git checkout -- eval/questions.jsonl`은 **저장하지 않은 모든 변경을 잃으므로** 먼저 백업 폴더를 확인 |

- 키워드가 본문에 **글자 그대로** 들어 있는 제도만 찾습니다 (의미 검색이 아님). 그래서 여러 말로 바꿔 검색해야 합니다.
- `[전국]/[지역]` 구분과 `[기한 지남?]/[진행중]`은 **추정**입니다. 틀릴 수 있으니 중요한 제도는 `show`로 원문을 확인하세요.
- 보조금24 응답의 실제 필드 이름은 별도로 확인이 필요합니다 (`fields` 명령, A의 `docs/INGEST_A.md`).
- 도구는 정답을 제안하거나 대신 정하지 않습니다. 판단은 사람이 합니다.
